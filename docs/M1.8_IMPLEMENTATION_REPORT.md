# M1.8 Implementation Report — Environmental Factor Registry + Unit/Declared-Unit Compatibility Gate

## Scope

M1.8 implements the environmental-data readiness layer only. It does **not** calculate carbon consequences, aggregate lifecycle modules, or publish a whole-life-carbon result.

The checkpoint adds four linked controls:

1. a long-form environmental-factor registry with provenance/licensing metadata;
2. explicit BoQ-to-factor-set assignments;
3. GWP/module-scope validation and double-counting guards;
4. a strict physical-unit compatibility gate before any future impact multiplication.

## Production-data boundary

The supplied M1.7/v2.1 evidence contains no populated physical intervention BoQ and no bundled source-backed environmental-factor dataset. Therefore:

- `inputs/component_boq.csv` remains header-only;
- `inputs/environmental_factors.csv` is header-only;
- `inputs/boq_environmental_factor_assignments.csv` is header-only;
- no factor or quantity is inferred from cost, labels, service-life data, or product-name similarity;
- `environmental_registry_status.json` reports `NO_ASSESSMENT_BOQ_LINES` rather than zero impact.

## Registry contract

`environmental_factors.py` validates:

- stable `factor_record_id`, `factor_set_id`, and `product_or_process_id`;
- one dataset/product/declared-unit/geography/provenance/license basis per factor set;
- supported GWP indicators: `GWP_TOTAL`, `GWP_FOSSIL`, `GWP_BIOGENIC`, `GWP_LULUC`;
- GWP indicator units normalized to `kgco2e`;
- explicit declared units;
- controlled lifecycle module scopes, including combined source scopes such as `A1-A3`;
- no overlap between combined and disaggregated source-module records for one factor-set/indicator;
- source type, verification status, data-quality status, license status, redistribution flag, and uncertainty semantics.

Negative environmental indicator values remain permitted where a documented source reports them; M1.8 does not reinterpret source values.

## Explicit factor assignment

`inputs/boq_environmental_factor_assignments.csv` separates factor selection from the physical BoQ. M1.8 supports:

- `EXACT_PRODUCT_ID`: BoQ `material_or_product_id` must equal factor `product_or_process_id`;
- `DOCUMENTED_PROXY`: identity mismatch is allowed only with an explicit mapping reference;
- `TEST_ONLY_SYNTHETIC`: restricted to test-only synthetic factors and requires fixture provenance.

Only `ASSESSMENT_INVENTORY` BoQ lines can receive executable environmental assignments. `INFORMATION_ONLY` lines remain non-executable.

## Unit/declared-unit gate

The compatibility layer resolves a future factor activity quantity without calculating impact. Allowed cases are:

- exact normalized unit match;
- explicit `kg -> t` or `t -> kg` conversion;
- a documented total `mass_kg` already attached to the BoQ row, used as an explicit bridge to mass-declared factors.

The gate blocks area-volume, area-mass without documented mass, density, thickness, geometry, cost, and other implicit conversions.

## GWP readiness gate

A BoQ assignment is not ready for the later carbon engine unless:

- units are explicitly compatible;
- `GWP_TOTAL` exists in the assigned factor set; and
- product-stage `GWP_TOTAL` covers either combined `A1-A3` or all three atomic `A1`, `A2`, `A3` source modules.

Disaggregated GWP indicators are retained but never summed to manufacture `GWP_TOTAL`.
