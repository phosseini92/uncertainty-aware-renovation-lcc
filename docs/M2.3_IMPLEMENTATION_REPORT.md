# M2.3 — B4 Replacement Transport Consequences

## Delivered scope

M2.3 adds transport consequences associated with canonical `B4_REPLACEMENT` lifecycle events. The transport process is physically the same type of freight process whose factor metadata are represented with source module scope `A4`, but because the transport occurs as part of a replacement event, its **reported building-level module is B4**. This prevents replacement transport from being double counted in initial A4.

No service-life draw is made in the carbon layer. Replacement timing, future identity and component generation come directly from the canonical lifecycle-event ledger and its M1.7 BoQ bridge.

## Architecture

A separate `boq_replacement_transport_assignments.csv` is used rather than extending the M2.2 initial-transport assignment table. This preserves the frozen initial A4 semantics and prevents implicit inheritance of a t=0 route into future replacements.

The executable chain is:

`canonical B4 event -> event/BoQ bridge -> replacement transport assignment -> documented mass -> documented distance -> tonne-km -> GWP_TOTAL transport factor -> B4 transport consequence`

The activity equation is:

`tonne-km = mass_kg / 1000 * distance_km`

and the consequence equation is:

`GWP_B4_transport = tonne-km * transport_factor_GWP_TOTAL`.

Every consequence row records the canonical `lifecycle_event_id`, future, scenario, component generation and exact event time. The source process factor scope stays `A4`; `reported_module` is `B4` and `consequence_type` is `B4_REPLACEMENT_TRANSPORT`.

## Guardrails

- one active replacement transport assignment per BoQ line;
- one active replacement transport flow identity per scenario;
- assessment-inventory BoQ only;
- explicit replacement basis only (`DOCUMENTED_REPLACEMENT_TRANSPORT`);
- exact scenario/parent scope matching;
- documented positive mass or supported mass-unit conversion;
- explicit distance (documented zero permitted, missing distance blocked);
- explicit GWP_TOTAL per tonne-km; disaggregated GWP indicators are never implicitly summed;
- route mode, vehicle class and load-factor basis must match the factor metadata;
- replacement transport uses canonical B4 event time and event ID and cannot appear in A4;
- initial and replacement assignment IDs must be disjoint;
- no carbon discounting, factor uncertainty or transport uncertainty.

## Production readiness limit

The production replacement-transport assignment file is intentionally header-only. Therefore the default production run is **not assessed** for B4 replacement transport; it is not a zero-carbon result. No replacement route, mass, distance or transport factor has been invented. A5, B6, C/D, residual value, future transport decarbonisation and whole-life-carbon headline results remain outside M2.3.

**Checkpoint result: PASS / freeze-ready for the implemented M2.3 scope.**
