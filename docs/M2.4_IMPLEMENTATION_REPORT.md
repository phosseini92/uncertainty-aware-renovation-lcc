# M2.4 — A5 Construction / Installation Carbon Consequences

## Scope

M2.4 implements only initial `A5.2` construction/installation activities and `A5.3` waste arising from the current construction/installation process. It is additive to M2.3. A5.1 pre-construction removal of existing works is deliberately excluded because the audited v3 architecture requires a separate removal inventory that also captures removed-material transport and waste handling without duplicating A5.3. A5.4 worker transport and B4 installation/waste are also deferred.

## Executable architecture

`construction_process_scenarios.csv` registers a documented construction process, its explicit activity unit and its assigned environmental factor set. `boq_construction_process_assignments.csv` maps that process to an assessment BoQ line with an explicit t0 activity quantity. The only M2.4 activity basis is `EXPLICIT_ACTIVITY_QUANTITY`; no process quantity is inferred from cost, labels or product quantity.

For A5.3, the assignment may state `NONE`, `BOQ_WASTE_RATE`, or `EXPLICIT_WASTE_QUANTITY`. A BoQ waste rate can use only the documented BoQ physical quantity or documented total mass. Unit reconciliation is limited to exact unit and kg↔tonne mass conversion. Missing compatible quantity/mass is blocked.

A5.2 requires `GWP_TOTAL` scoped exactly to `A5.2`; A5.3 requires `GWP_TOTAL` scoped exactly to `A5.3`. GWP_TOTAL is not reconstructed from disaggregated indicators. Consequences occur at `t=0`, generation 0, and do not use replacement lifecycle-event IDs. Valid rows are appended to the shared carbon consequence ledger with consequence types `A5_2_CONSTRUCTION_INSTALLATION` and `A5_3_CURRENT_CONSTRUCTION_WASTE`.

## Double-counting boundary

Pre-existing material removed to enable renovation is not accepted as A5.3 current-construction waste. M2.4 has no A5.1 removal input and therefore cannot silently count that material. The later A5.1 milestone must use a dedicated pre-construction removal inventory. B4 installation and B4 replacement-generated waste likewise remain attached to future B4 work and are not generated by this initial A5 engine.

## Production-data integrity

The inherited project contains no documented construction activity, installation energy/equipment activity, or current-construction waste data. Both new production input files are therefore header-only. The default A5 engine status is `NO_ASSESSMENT_BOQ_LINES`; missing data are not converted to zero impact.

## Validation

Ten new tests were added. The closed-form synthetic fixture gives A5.2 = `20 kWh × 0.5 kgCO2e/kWh = 10 kgCO2e` and A5.3 = `1000 kg × 5% × 0.2 kgCO2e/kg = 10 kgCO2e` per future. Tests also verify explicit-waste equivalence, no-waste semantics, missing-mass blocking, exact submodule factor scope, duplicate/scope guards, t0 and horizon invariance, and isolation of prior subengines.

The repository contains **162 tests** and all were verified passing in module chunks. Python byte-compilation passed. A full default 10,000-future run with convergence diagnostics and charts completed successfully.

For production parity, M2.4 was run independently with 10,000 futures and seed `20260726` for `legacy_30`, `levels_50`, and `rics_60`. Against the M2.3 audited outputs, all **58/58 common non-manifest outputs are byte-for-byte identical** at every horizon.

**Checkpoint result: PASS / freeze-ready for the implemented M2.4 scope.**
