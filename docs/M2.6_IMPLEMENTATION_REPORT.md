# M2.6 Implementation & Audit Report

## Milestone

**M2.6 — B4 Replacement Event Process Completion**

M2.6 completes the non-product, non-inbound-transport process family attributable to canonical `B4_REPLACEMENT` events. It is additive to the frozen M2.5 baseline.

## Implemented consequence roles

Each executable assignment is attached to a canonical replacement event and is reported in **B4**:

- `B4_REPLACEMENT_INSTALLATION` — source process factor may use `A5.2`;
- `B4_REPLACEMENT_REMOVAL` — source process factor may use `A5.1` or `C1`;
- `B4_REPLACEMENT_WASTE_TRANSPORT` — source transport-process factor uses `A4`;
- `B4_REPLACEMENT_WASTE_PROCESSING` — source process factor uses `C3`;
- `B4_REPLACEMENT_WASTE_DISPOSAL` — source process factor uses `C4`.

The source-process module remains visible in `source_factor_module_scope`; `reported_module` is always `B4`. This is deliberate event ownership, not factor relabelling. It prevents replacement consequences from being duplicated into initial A modules or terminal C-stage accounting.

## Input and gates

New production input: `inputs/b4_event_process_assignments.csv`. It is intentionally header-only because the inherited demonstrator contains no source-backed replacement-installation/removal/waste-process dataset.

Assignments require explicit stable IDs, BoQ/scenario scope, process role, factor registry, factor set, expected source module, quantity basis, mapping evidence, source status/reference and retrieval date. Supported quantity bases are explicit activity, BoQ quantity, documented BoQ mass, and documented mass × distance tonne-km. No cost-to-quantity, area-to-mass, density, route, or activity inference is introduced.

The event-BoQ bridge is checked against the canonical lifecycle ledger for future, scenario, component, lineage, generation and event type. Non-B4 events cannot generate M2.6 consequences.

## Golden validation

Synthetic event: one canonical B4 replacement with a 1,000 kg BoQ line.

- installation: `20 kWh × 0.5 kgCO2e/kWh = 10 kgCO2e`;
- removal: `8 kWh × 0.25 = 2 kgCO2e`;
- outbound waste transport: `1 t × 100 km × 0.1 = 10 kgCO2e`;
- processing: `1,000 kg × 0.2 = 200 kgCO2e`;
- disposal: `1,000 kg × 0.1 = 100 kgCO2e`.

Total assessed M2.6 process consequences for that event: **322 kgCO2e**, all reported in B4 and linked to the same lifecycle event ID.

## Scientific boundaries

M2.6 does not introduce B6 operational carbon, B2/B3/B5, terminal C1–C4, Module D, residual value, carbon discounting, future factor trajectories, or environmental-factor uncertainty sampling. It does not create a whole-life-carbon headline. Production missing data remain **not assessed**, never zero.

## Regression and parity

Independent 10,000-future runs with seed `20260726` were executed at `legacy_30`, `levels_50`, and `rics_60`. For each horizon, all **71 common non-manifest M2.5 outputs are byte-identical**. The only new production outputs are the M2.6 assignment resolution, compatibility, coverage, summary and status files.

Canonical lifecycle-event counts remain 94,164 / 209,348 / 256,953 for 30 / 50 / 60 years. Production M2.6 consequence rows are zero because the production assignment input is unpopulated.

A full default 10,000-future run with convergence diagnostics and charts completed successfully.
