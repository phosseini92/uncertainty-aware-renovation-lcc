# M1.3 stable IDs + explicit comparison lineage: implementation and parity audit
## Scope
M1.3 replaces the default run's transitional identity proxies with explicit stable scenario/component/type IDs and explicit cross-scenario comparison lineage. It does not change v2.1 economic equations, random streams, replacement timing, the 30-year analysis horizon, physical quantities, retained remaining-life semantics, or any carbon calculation.
## Production changes
- Added `identity.py` for strict stable-ID validation and deterministic `legacy_` compatibility fallbacks.
- Migrated `inputs/renovation_scenarios.csv` with explicit `scenario_id`.
- Migrated `inputs/components.csv` with explicit `scenario_id`, `component_instance_id`, `component_type_id`, and `comparison_lineage_id`.
- Canonical event construction now receives stable IDs directly; display strings no longer participate in `event_id`.
- Added lineage guards: one lineage must map to exactly one component type and one lifetime uncertainty stream.
- Kept display `scenario`/`component` strings as the legacy economic/reporting keys so public v2.1 outputs remain compatible.
- Legacy scenario/component files without IDs remain accepted, but their generated compatibility IDs are visibly prefixed `legacy_`.
