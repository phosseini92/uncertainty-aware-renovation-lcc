# M2.6 input guide — B4 replacement-event processes

`inputs/b4_event_process_assignments.csv` maps documented per-replacement activities to a BoQ line and a source factor set. The production file is intentionally header-only until source-backed data are supplied.

Required columns:

- `assignment_id`, `boq_line_id`, `scenario_id`, `b4_flow_id`
- `process_role`: `INSTALLATION`, `REMOVAL`, `OUTBOUND_WASTE_TRANSPORT`, `WASTE_PROCESSING`, or `WASTE_DISPOSAL`
- `factor_registry`: `ENVIRONMENTAL` or `TRANSPORT`, constrained by role
- `factor_set_id`, `expected_source_module`
- `quantity_basis`: `EXPLICIT_ACTIVITY`, `BOQ_QUANTITY`, `BOQ_MASS`, or `BOQ_TONNE_KM`
- `activity_quantity`, `activity_unit`, `distance_km` as required by the selected basis
- `active`, `mapping_basis`, `mapping_reference`, `source_status`, `source_reference`, `retrieval_date`, `notes`

Source-module gates are exact: installation → `A5.2`; removal → `A5.1` or `C1`; outbound waste transport → `A4`; waste processing → `C3`; waste disposal → `C4`. These are source-process scopes only. Valid consequences remain reported in `B4` because they are attributable to the canonical replacement event.

No replacement process is inferred from the initial construction/removal inputs. Missing mappings remain not assessed. Synthetic fixtures must use `TEST_ONLY_SYNTHETIC` provenance and mapping basis.
