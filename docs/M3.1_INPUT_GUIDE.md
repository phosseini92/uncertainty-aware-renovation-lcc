# M3.1 Input Guide — B6 Operational Energy

## `inputs/operational_energy_flows.csv`

Each row is one explicit annual physical flow over a non-overlapping analysis-year interval.

Required fields:

- `energy_flow_id` — stable row ID;
- `scenario_id` — existing scenario ID;
- `carrier_id` — stable carrier ID such as `electricity`;
- `flow_type` — `IMPORTED`, `GENERATED`, `SELF_CONSUMED`, or `EXPORTED`;
- `annual_quantity_kwh` — documented annual quantity, finite and nonnegative;
- `first_analysis_year`, `last_analysis_year` — inclusive active interval;
- `b6_factor_schedule_id` — required only for `IMPORTED` rows;
- provenance fields — `source_status`, `source_reference`, `retrieval_date`, `notes`.

No flow is inferred from cost, energy savings, PV size, building label, or another flow. Missing data require an absent row or blocked mapping; they are not encoded as zero. An explicit documented zero import is allowed and produces no zero-impact consequence row.

## `inputs/operational_energy_factor_schedule.csv`

Each row maps one analysis year to one calendar year and one environmental factor set.

Required fields:

- `schedule_id`;
- `carrier_id`;
- `analysis_year`;
- `calendar_year`;
- `factor_set_id`;
- provenance fields.

The referenced factor set must provide exactly one `GWP_TOTAL` factor with source module `B6` and declared unit `kwh`. Missing schedule years block execution. M3.1 performs no interpolation, extrapolation, or decarbonisation inference.

## PV / onsite generation bookkeeping

For each scenario/carrier/year:

`SELF_CONSUMED + EXPORTED <= GENERATED`

The remainder may represent documented curtailment/losses. `EXPORTED` is tracked but receives no B6 credit and is not netted against imports. A later Module-D milestone may use the explicit export flow under a separately declared accounting convention.
## Runtime reporting metadata (M3.1.1 hardening)

`inputs/model_config.json` explicitly declares:

- `assessment_convention = EN15978_2026_INFORMED`;
- `generated_energy_reporting_approach = PHYSICAL_FLOWS_B6_IMPORT_ONLY_D2_DEFERRED`;
- `factor_extrapolation_policy = ERROR_IF_MISSING`.

These fields describe the selected reporting policy; they do not change the M3.1 numerical equation. The current release intentionally rejects any extrapolation policy other than `ERROR_IF_MISSING` and calculates no D2/export credit.

### Calendar year versus factor `reference_year`

`operational_energy_factor_schedule.calendar_year` is the **application year** to which a factor is assigned. `environmental_factors.reference_year` is the **dataset/source reference vintage** recorded for provenance. They are not required to be equal. Any claim that a factor represents a future-year trajectory must therefore be supported by the explicit schedule/source evidence rather than inferred from `reference_year`.
